# Interactive Profile README — Design

## Goal

Make `NikFarees/NikFarees` (GitHub profile README) feel more interactive and dynamic without client-side JavaScript, since GitHub strips `<script>` tags from rendered READMEs. Replace plain `---` markdown dividers with a nicer visual treatment. Add collapsible stack sections and live/auto-updating stats.

## Constraint

GitHub sanitizes README HTML on render: no `<script>`, no `<style>` blocks, no iframes. All "interactivity" must come from:
- Native HTML elements GitHub allows (`<details>`/`<summary>`)
- `<img>` references to externally-hosted or repo-hosted SVG/PNG that are themselves animated (CSS/SMIL) or regenerated server-side
- GitHub Actions workflows that commit updated content/images back to the repo on a schedule

## Layout (top to bottom)

1. `banner.png` — unchanged, existing top image.
2. Typing-effect line — `<img>` pointing at a typing-SVG generator (e.g. `readme-typing-svg.demolab.com`), rotating through: "Backend Developer", "Laravel & Filament", "Next.js when needed", "Auction platform · 100+ concurrent users". No secret required, no repo-side generation.
3. Intro paragraph — unchanged.
4. Gradient SVG rule — replaces `---`. Thin horizontal gradient bar, dark-theme colors matching existing badge palette.
5. **Stack** — five `<details><summary>CategoryName</summary>...</details>` blocks (Languages / Backend / Frontend / DevOps / Database), each collapsed by default, containing the existing shields.io badges for that category.
6. Gradient SVG rule.
7. **Live Stats**
   - GitHub stats card: `<img>` to `github-readme-stats.vercel.app` API, no secret.
   - Streak stats card: `<img>` to `github-readme-streak-stats.herokuapp.com` API, no secret.
   - Contribution snake: `<picture>` element with dark/light SVG variants, sourced from the repo's `output` branch (generated by the `snake.yml` workflow).
   - WakaTime coding stats: HTML comment-delimited block `<!--START_SECTION:waka--> <!--END_SECTION:waka-->`, auto-filled by the `waka-readme.yml` workflow.
8. Gradient SVG rule.
9. **Contact** — unchanged badges.

## New files

### `.github/workflows/snake.yml`
- Triggers: `schedule` (daily, `0 0 * * *`), `workflow_dispatch`, `push` to `main`.
- Uses `Platane/snk@v3` to render the contribution graph as an eaten-by-snake animation.
- Outputs both `github-contribution-grid-snake-dark.svg` and `-light.svg`.
- Pushes output to an orphan `output` branch (keeps `main` history clean).
- README references both SVGs via a `<picture>` tag switching on `prefers-color-scheme`.
- Failure mode: run fails silently (rate limit / outage) → last-committed SVG on `output` branch stays live, no broken image. Manual re-run via `workflow_dispatch`.

### `.github/workflows/waka-readme.yml`
- Triggers: `schedule` (daily), `workflow_dispatch`.
- Uses `anmol098/waka-readme-stats@master`.
- Requires repo secret `WAKATIME_API_KEY` (added manually by user via GitHub repo Settings → Secrets — not settable by an agent).
- Commits updated content into the `<!--START_SECTION:waka--> / <!--END_SECTION:waka-->` block in `README.md` using the default `GITHUB_TOKEN` (no extra secret needed for the commit itself).
- Failure mode: run fails → block keeps last-known-good content, no broken README section.

## Out of scope

- No real client-side JavaScript (not possible in GitHub-rendered READMEs).
- No new project/repo listing section (GitHub's native "Pinned" feature already covers this, per current profile).
- No changes to `banner.png` itself.
